# WhatsApp, social messages and requested calls

Priority: P2 conversion channel, available whenever requested | Owner: Kaushik

## Goal

Continue a conversation in the channel the buyer chooses. The verified-number list is not a cold-calling or cold-WhatsApp campaign.

## Setup

1. Use a truthful GardenSuite/Sarbani Associates business identity and current business contact details.
2. Add an optional user-initiated WhatsApp action after the report or demonstration page. The visitor must actually send the message; merely clicking a button is not proof of an inbound conversation.
3. Offer a requested-call form with number, preferred time, topic and a clear call request. Do not put the mobile field in the basic report-download form.
4. Store the request source, time, channel and permitted purpose against the estate/contact. Check suppression before a business-initiated reply or follow-up.
5. Use existing human messaging for the pilot. Do not introduce an API/broadcast tool just to serve a handful of enquiries.

GardenSuite's chosen rule is specific channel permission or a relevant inbound request. This plan is not a statement that all platform policies use the same wording. Recheck the current [WhatsApp Business policy](https://business.whatsapp.com/policy) before any later automated messaging setup.

## Draft response

Hello [Name], this is Kaushik from GardenSuite, Sarbani Associates. You asked about [attendance/report/demo]. Would you prefer the short sample here, or an online demonstration?

For a requested call, state the agreed time and topic. If the call is missed, leave a brief message in the permitted channel and offer a new time; do not repeatedly call.

## Handling email and social replies

A positive email reply is permission to answer the email. Ask before moving to WhatsApp or calling unless the buyer already requested that channel. If a group member asks for a private link, send that link; it does not authorize an unrelated drip sequence.

Do not interpret silence, a download or a valid number as a sales-call request. If somebody explicitly refuses contact, stop and record the instruction across linked channels/accounts as appropriate. A later data import must not override it.

## Do

Keep the first response tied to the request, identify yourself, confirm a suitable time, and record demo outcomes. Use only the media the person requested. Keep support conversations separate from marketing permission.

## Do not

Call scraped owner mobiles, broadcast the old WhatsApp queue, send a cold permission request to an unconsenting mobile, use another number after an objection, or ask staff to disclose a private owner number. Do not claim automated WhatsApp setup is complete when only a link exists.

## Goals and acceptance criteria

- [ ] Every proactive call/message has a recorded relevant request or channel permission.
- [ ] Caller identity and business purpose are clear.
- [ ] Inbound links and requested-call routing are tested with controlled records.
- [ ] First useful response targeted within one working day; measure actual response time.
- [ ] Every completed conversation records owner role, need and agreed next step.
- [ ] Stop/objection handling prevents further automated activity across linked channels.

Success is an agreed next step or useful qualification, not number of calls placed. Do not use a weekly dial quota.
