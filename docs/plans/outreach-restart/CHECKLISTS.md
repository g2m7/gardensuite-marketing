# Outreach Working Checklists

Use these during implementation. Acceptance evidence belongs in the system of record or the gate record, not only in a checked box.

## 1. Strategy approval checklist

- [ ] Geography is West Bengal and Assam only
- [ ] Minimum size is 50 hectares
- [ ] Corporate exclusion list or rule is approved
- [ ] Target roles are approved
- [ ] Email-first order is approved
- [ ] WhatsApp permission gate is approved
- [ ] LinkedIn is outside the first pilot
- [ ] Attendance is the primary offer
- [ ] Pipeline stages are approved
- [ ] Cadence is approved
- [ ] Pilot size and state split are approved
- [ ] Success and pause rules are approved
- [ ] Outreach owner and backup are named
- [ ] Demo owner and backup are named
- [ ] Launch, pause, resume, and scale authorities are named

## 2. System-of-record checklist

- [ ] One canonical tool is selected
- [ ] Accounts structure exists
- [ ] Contacts structure exists
- [ ] Activities structure exists
- [ ] Suppression structure exists
- [ ] Message Versions structure exists
- [ ] Pilot Batches structure exists
- [ ] Permanent IDs are used
- [ ] Required fields cannot be skipped in send-ready records
- [ ] Controlled values exist for stages, roles, results, and suppression reasons
- [ ] Account-level active-contact lock exists
- [ ] Suppression blocks send-ready views
- [ ] Three sample estates pass workflow testing
- [ ] Editor and backup process are documented

## 3. Per-estate research checklist

- [ ] Estate name and aliases checked
- [ ] Estate status is current
- [ ] State is West Bengal or Assam
- [ ] District and address are current
- [ ] At least 50 hectares is proven
- [ ] Hectare source and date are recorded
- [ ] Current owner or controlling group is proven
- [ ] Ownership source and date are recorded
- [ ] Corporate exclusion result is Clear
- [ ] Duplicate-account check passed
- [ ] Account owner is named
- [ ] Qualification reason is recorded

## 4. Per-contact research checklist

- [ ] Full name is current
- [ ] Raw title is recorded
- [ ] Role maps to an approved category
- [ ] Role source and date are recorded
- [ ] Email source is recorded
- [ ] Email is normalized
- [ ] Email verification is current
- [ ] Generic inbox status is clear
- [ ] Phone source is recorded if phone is stored
- [ ] WhatsApp permission is Yes, No, Unknown, or Existing Relationship
- [ ] Contact and account suppression are clear
- [ ] Contact is marked primary or secondary
- [ ] Second reviewer approved the contact

## 5. Pilot-batch QA checklist

- [ ] Batch has 20 unique estate accounts or approved smaller count
- [ ] State split is 10 West Bengal and 10 Assam, or exception is recorded
- [ ] One primary contact per estate
- [ ] Every account is Qualified
- [ ] Zero accounts are Manual Review
- [ ] Zero contacts are suppressed
- [ ] Zero accounts are on the corporate exclusion list
- [ ] Role and email freshness meet the approved limit
- [ ] Every row has two reviewers
- [ ] Batch ID, version, and freeze time are recorded

## 6. Message writing checklist

- [ ] Approved attendance sequence is selected
- [ ] Attendance problem is specific
- [ ] One GardenSuite mechanism is explained
- [ ] Sarbani Associates trust point is used where helpful
- [ ] One CTA only
- [ ] Email 1 is no more than the approved length
- [ ] Follow-up adds a new point
- [ ] No `just checking in`
- [ ] No attachment or image
- [ ] No unsupported result or guarantee
- [ ] Uses `helps stop proxy attendance`
- [ ] Simple English test passed
- [ ] Generic-software copy test passed
- [ ] Subject line rules passed
- [ ] Opt-out wording is clear
- [ ] Version and approvals are recorded

## 7. Sender setup checklist

- [ ] Named sender approved
- [ ] Sending domain approved
- [ ] Mailbox approved
- [ ] Snov.io account and Trial plan verified
- [ ] Domain SMTP/IMAP mailbox connection verified
- [ ] New Snov.io campaigns approved
- [ ] Reply owner and backup named
- [ ] SPF passed
- [ ] DKIM passed
- [ ] DMARC and alignment passed
- [ ] TLS confirmed
- [ ] Reply route tested
- [ ] Seed inbox placement tested
- [ ] Mailbox warmup or history accepted
- [ ] Daily cap recorded
- [ ] Provider warnings checked
- [ ] No legacy list or template is active
- [ ] Reply exit, unsubscribe exit, and re-entry settings pass

## 8. Suppression checklist

- [ ] Master register is available to sender workflow
- [ ] Email and phone are normalized
- [ ] Contact-level scope works
- [ ] Account-level scope works
- [ ] Corporate exclusion scope works
- [ ] Stop request test passed
- [ ] Unsubscribe test passed
- [ ] Hard bounce test passed
- [ ] Spam complaint process is documented
- [ ] Later-import reactivation test failed safely
- [ ] Manual sending uses the same check
- [ ] Operator and time are recorded for each event

## 9. Internal dry-run checklist

- [ ] Seed list contains no external prospects
- [ ] Approved attendance sequence tested
- [ ] Snov.io fields render correctly
- [ ] Missing required field blocks send or uses the approved fallback
- [ ] Reply route works
- [ ] Snov.io reply exit works
- [ ] Positive reply handoff works
- [ ] Not-now classification works
- [ ] Stop request suppresses immediately
- [ ] Hard bounce triggers pause
- [ ] Account lock blocks a second active contact
- [ ] Pause prevents later touches
- [ ] Activities reconcile with sends
- [ ] Critical defects are zero
- [ ] G6 reviewer signed evidence

## 10. Daily pre-send checklist

- [ ] No unresolved incident
- [ ] Provider health is normal
- [ ] Today's contacts are in the frozen batch
- [ ] Today's touch is due
- [ ] Account has no reply or hold
- [ ] Contact has no bounce or suppression
- [ ] Account remains Qualified
- [ ] No second contact at the account is active
- [ ] Message version matches the approved attendance sequence
- [ ] Final suppression check time is recorded
- [ ] Daily cap is not exceeded
- [ ] Reply and demo owners are available

## 11. Daily close checklist

- [ ] Sent count matches activity count
- [ ] Bounces are suppressed
- [ ] Complaints are reviewed
- [ ] Replies are classified
- [ ] Positive replies have next actions
- [ ] Stop requests are suppressed
- [ ] Overdue actions are escalated
- [ ] Deviations are recorded
- [ ] Daily status is sent to the accountable owner

## 12. Reply checklist

- [ ] Stop future touches first
- [ ] Read account history
- [ ] Classify the reply
- [ ] Answer the actual question
- [ ] Record a clear summary
- [ ] Assign the next owner
- [ ] Set a next-action date
- [ ] Record channel permission if provided
- [ ] Hand off to demo owner when appropriate
- [ ] Apply suppression immediately when requested

## 13. Incident checklist

- [ ] Pause remaining sends
- [ ] Record time and affected records
- [ ] Preserve provider logs
- [ ] Notify accountable owner
- [ ] Apply suppression if needed
- [ ] Identify root cause
- [ ] Fix the failed control
- [ ] Retest the exact failure
- [ ] Recheck unsent accounts
- [ ] Record written resume or stop decision

## 14. Pilot closeout checklist

- [ ] Every account has final outcome
- [ ] Every send has an activity
- [ ] Every reply has a category
- [ ] Every positive reply has an outcome or next action
- [ ] Every suppression event is complete
- [ ] Qualification QA rerun on all accounts
- [ ] Metrics use raw counts and percentages
- [ ] Results split by state, role, touch, and version
- [ ] Repeated objections are summarized
- [ ] Incidents and deviations are included
- [ ] G8 evidence approved
- [ ] G9 decision is Stop, Repair, Repeat 20, or Scale
- [ ] Current strategy is updated if decisions changed
